# Бэкенд-платформа онлайн-обучения "LMS-API" (CI/CD Автоматизация)

## Описание проекта:
Проект представляет собой специализированный REST API бэкенд-сервер для LMS-системы [config:settings]. Экосистема проекта полностью контейнеризирована и оснащена автоматическим конвейером тестирования и деплоя GitHub Actions (CI/CD) [Задание 1, 2, *].

---

## 📋 Настройка автоматического CI/CD конвейера (Задание 2)

При каждом отправлении кода (`git push`) в репозиторий автоматически запускается сценарий `.github/workflows/deploy.yaml` [Задание 2]. Он тестирует проект, а затем подключается к удаленному серверу по SSH, пересобирает Docker-контейнеры и применяет миграции [Задание 1, 2, *].

### Инструкция по настройке безопасных переменных (GitHub Secrets):
Чтобы конвейер мог получить доступ к вашему удаленному серверу, зайдите в настройки вашего репозитория на сайте GitHub:
1. Перейдите во вкладку **Settings** ➡️ **Secrets and variables** ➡️ **Actions**.
2. Нажмите кнопку **New repository secret** и добавьте по очереди три секретные переменные [Задание 1, 2]:
   * `SERVER_HOST` — публичный IP-адрес вашего удаленного арендованного сервера.
   * `SERVER_USER` — имя пользователя для подключения (например, `root`).
   * `SERVER_SSH_KEY` — содержимое вашего приватного ключа авторизации SSH (начинается с `-----BEGIN OPENSSH PRIVATE KEY-----`).

## 🐋 Локальный запуск приложения через Docker Compose

### 1. Настройка конфигурации `.env`
Создайте в корне проекта файл **`.env`** на основе шаблона `.env.example` [Задание 1-3].

### 2. Сборка и запуск всех служб
Выполните в терминале вашего проекта команду оркестрации:
```bash
docker compose up --build
```
Docker Compose автоматически поднимет в параллели 5 контейнеров: веб-приложение Django, PostgreSQL, Redis, Celery Worker и Celery Beat [config:settings, config:celery].

### 3. Применение миграций локально
```bash
docker compose exec web python manage.py migrate
```
