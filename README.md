# Бэкенд-платформа онлайн-обучения "LMS-API"

## Описание проекта:
Проект представляет собой специализированный бэкенд-сервер для LMS-системы (Learning Management System), разработанный в рамках концепции SPA (Single Page Application) [config:settings]. Сервер функционирует исключительно в режиме REST API, принимая и отдавая строго структурированные JSON-данные. Платформа построена на базе фреймворка Django с использованием инструментария Django Rest Framework (DRF) и СУБД PostgreSQL [Задание 1, 2].

## 📋 Чек-лист проверки функционала (Урок 31)

### 1. Архитектура и Базовый CRUD (Урок 30.1)
- [ ] **Интеграция DRF (Задание 1):** К проекту успешно подключен пакет `djangorestframework`, обеспечивающий сериализацию данных и маршрутизацию эндпоинтов.
- [ ] **Кастомная модель пользователя (Задание 2):** В приложении `users` развернута модель `User` на базе `AbstractBaseUser` [users:models]. Стандартная авторизация по `username` полностью заменена на уникальный `email` [users:models]. Добавлены профильные поля: телефон, город и аватарка.
- [ ] **Модели материалов обучения (Задание 2):** В приложении `materials` спроектированы сущности **Курс** и **Урок** [materials:models]. Между ними реализована связь «один-ко-многим» через `ForeignKey`.
- [ ] **CRUD для Курсов и Уроков (Задание 3):** С помощью `ModelViewSet` развернут полный автоматический набор API-эндпоинтов для курсов [materials:views]. На базе цепочки Generic-классов вручную описаны изолированные эндпоинты для всех операций с уроками.

### 2. Продвинутые Сериализаторы и Финансы (Урок 30.2)
- [ ] **Подсчет уроков (Задание 1):** В `CourseSerializer` успешно добавлено динамическое поле `lessons_count` на базе `SerializerMethodField()` [materials:serializers]. Поле возвращает точное и корректное число связанных уроков.
- [ ] **Вложенная структура (Задание 3):** Реализован сквозной вывод уроков внутри курса [materials:serializers]. При запросе информации о курсе в JSON-ответе штатно выводится массив `lessons`.
- [ ] **Модель платежей и Фикстуры (Задание 2):** В приложении `users` создана модель `Payment` [users:models]. Написана и отлажена кастомная команда управления `fill_payments` [users:management:commands:fill_payments]. Данные групп выгружены в чистую UTF-8 фикстуру `groups.json`.
- [ ] **Фильтрация и Сортировка API (Задание 4):** Эндпоинт списка платежей оснащен гибкой фильтрацией `django-filter` по курсам, урокам, типам оплаты и двусторонней сортировкой по датам [users:views].

### 3. Авторизация и Разграничение Прав Доступа (Урок 31)
- [ ] **JWT-авторизация (Задание 1):** Проект переведен на строгую токенизированную защиту через `djangorestframework-simplejwt` [config:settings]. Эндпоинты получения (`token/`) и обновления токенов (`token/refresh/`) работают штатно [users:urls]. Глобальный API закрыт проверкой `IsAuthenticated`.
- [ ] **Открытая регистрация (Задание 1):** Разработан открытый эндпоинт `users/register/` с правами `AllowAny` [users:views, users:urls]. Реализованы проверки уникальности, хэширование паролей (`set_password`) и обработка исключений.
- [ ] **Модераторский доступ (Задание 2):** Создана группа "Модераторы" и кастомный permission-класс `IsModerator` [users:permissions]. Настроено автоматическое разделение по action во ViewSet [materials:views]. Модераторы имеют право читать и изменять контент, но лишены прав на создание (`create`) и удаление (`destroy`).
- [ ] **Права владельцев (Задание 3):** Реализован класс `IsOwner` для защиты контента на уровне объектов [users:permissions]. В методах `perform_create` настроена автоматическая привязка сущностей к текущему аутентифицированному пользователю [materials:views]. Обычные пользователи видят, меняют и удаляют только свои записи.
- [ ] **Защита чужих профилей (Дополнительное задание):** Реализовано динамическое переключение сериализаторов профиля [users:views]. При просмотре чужого аккаунта пароль, фамилия и история оплат автоматически вырезаются из JSON-выдачи [users:serializers].

## Инструкция по установке и запуску:

1. **Установите все зависимости проекта через Poetry:**
   ```bash
   poetry install
   ```
2. **Настройте файл переменных окружения `.env` в корне проекта:**
   ```env
   SECRET_KEY="ваш_уникальный_секретный_ключ"
   DEBUG=True
   DB_NAME=lms_db
   DB_USER=postgres
   DB_PASSWORD=ваш_пароль_от_postgres
   DB_HOST=127.0.0.1
   DB_PORT=5432
   ```
3. **Убедитесь, что сервер PostgreSQL запущен, и создайте базу данных `lms_db`.**
4. **Сгенерируйте и примените миграции базы данных:**
   ```bash
   poetry run python manage.py makemigrations users materials
   poetry run python manage.py migrate
   ```
5. **Создайте системную группу модераторов и наполните базу платежами:**
   ```bash
   poetry run python manage.py create_moderators
   poetry run python manage.py fill_payments
   ```
6. **Запустите локальный API-сервер:**
   ```bash
   poetry run python manage.py runserver
   ```

## Базовые эндпоинты API для тестирования в Postman:

* **Регистрация нового студента (Доступно всем):**
  `POST -> 127.0.0.1:8000/api/users/register/`
* **Авторизация (Получение Access/Refresh токенов):**
  `POST -> 127.0.0.1:8000/api/users/token/`
* **Список курсов (Требуется токен в Headers: `Authorization: Bearer <token>`):**
  `GET -> 127.0.0.1:8000/api/courses/`
* **Список уроков:**
  `GET -> 127.0.0.1:8000/api/lessons/`
* **Просмотр личного профиля (Полные данные):**
  `GET -> 127.0.0.1:8000/api/users/profile/<свой_id>/`
* **Просмотр чужого профиля (Только публичные скрытые данные):**
  `GET -> 127.0.0.1:8000/api/users/profile/<чужой_id>/`
