# Бэкенд-платформа онлайн-обучения "LMS-API"

## Описание проекта:
Проект представляет собой специализированный бэкенд-сервер для LMS-системы (Learning Management System), разработанный в рамках концепции SPA (Single Page Application) [config:settings]. Сервер функционирует исключительно в режиме REST API, принимая и отдавая строго структурированные JSON-данные. Платформа построена на базе фреймворка Django с использованием инструментария Django Rest Framework (DRF) и СУБД PostgreSQL [Задание 1, 2].

## 📋 Чек-лист проверки функционала (Урок 30.2)

### 1. Сериализаторы и агрегация контента
- [ ] **Подсчет уроков (Задание 1):** В `CourseSerializer` успешно добавлено динамическое поле `lessons_count` на базе `SerializerMethodField()` [materials:serializers]. Поле возвращает точное и корректное число связанных уроков.
- [ ] **Вложенная структура (Задание 3):** Реализован сквозной вывод уроков внутри курса [materials:serializers]. При запросе информации о курсе в JSON-ответе штатно выводится массив `lessons` со всеми деталями каждого урока.

### 2. Финансовый учет и фикстуры
- [ ] **Модель платежей (Задание 2):** В приложении `users` создана модель `Payment` [users:models]. Модель содержит защищенные Foreign-ссылки на пользователя, курс, урок, фиксирует дату, сумму (`DecimalField`) и способ оплаты [users:models].
- [ ] **Автоматическое наполнение базы (Задание 2):** Написана и отлажена кастомная команда управления `fill_payments` [users:management:commands:fill_payments]. Очистка таблиц и первичное заполнение происходят без ошибок.

### 3. Фильтрация, поиск и сортировка API
- [ ] **Сортировка по датам (Задание 4):** Эндпоинт списка платежей поддерживает двустороннее упорядочивание [users:views]. Параметры `?ordering=payment_date` (по возрастанию) и `?ordering=-payment_date` (по убыванию) отрабатывают корректно.
- [ ] **Фильтрация по контенту (Задание 4):** Выборка результатов строго соответствует переданным GET-параметрам фильтрации для курсов (`?paid_course=<id>`) и уроков (`?paid_lesson=<id>`) [users:views].
- [ ] **Фильтрация по типу оплаты (Задание 4):** Фильтр корректно разделяет платежи по способу оплаты (`?payment_method=Наличные` или `Перевод`) [users:views].

### 4. Дополнительный функционал
- [ ] **Финансовая история пользователя (Дополнительное задание):** Сериализатор профиля расширен [users:serializers]. В JSON-ответе личного кабинета отдается полная вложенная история всех совершенных пользователем платежей.

## Инструкция по установке и запуску:

1. **Установите все зависимости проекта через Poetry:**
   ```bash
   poetry install
   ```
2. **Настройте файл переменных окружения `.env` в корне проекта:**
   ```env
   SECRET_KEY="ваш_уникальный_секретный_ключ"
   DEBUG=True
   DB_NAME=lms_db
   DB_USER=postgres
   DB_PASSWORD=ваш_пароль_от_postgres
   DB_HOST=127.0.0.1
   DB_PORT=5432
   ```
3. **Убедитесь, что сервер PostgreSQL запущен, и создайте базу данных `lms_db`.**
4. **Сгенерируйте и примените миграции базы данных:**
   ```bash
   poetry run python manage.py makemigrations users materials
   poetry run python manage.py migrate
   ```
5. **Запустите команду автоматического наполнения базы тестовыми финансовыми данными:**
   ```bash
   poetry run python manage.py fill_payments
   ```
6. **Запустите локальный API-сервер:**
   ```bash
   poetry run python manage.py runserver
   ```

## Примеры эндпоинтов API для тестирования в Postman или браузере:

* **Вложенный список курсов (+ счетчик и список уроков):**
  `127.0.0.1:8000/api/courses/`
* **Полный список финансовых платежей платформы:**
  `127.0.0.1:8000/api/users/payments/`
* **Сортировка платежей от самых новых к старым:**
  `127.0.0.1:8000/api/users/payments/?ordering=-payment_date`
* **Фильтрация платежей, сделанных только переводом на счет:**
  `127.0.0.1:8000/api/users/payments/?payment_method=Перевод`
* **Просмотр профиля пользователя с его личной историей оплат:**
  `127.0.0.1:8000/api/users/profile/<id>/update/`
